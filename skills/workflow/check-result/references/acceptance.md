# Ticket 验收清单

每张 ticket 对应 `.adev/<feature>/acceptance/<NN>-<slug>.md`；ticket 中用 `**验收清单：**` 链接它。实现完成且构建检查通过后一次性交付，覆盖全部标准。已有清单原地更新，保留用户勾选、问题与历史；不生成多份结果副本。

清单使用 Markdown 列表，不使用表格。每项有稳定编号、前置条件、具体操作、观察位置和明确通过标准；不能只写“验证正常”。注明实际启动命令/入口、环境、所需数据或设备及日志路径。非 C# 项目按实际验证方式填写。

以下为生成模板，交付时替换所有占位内容；条目数量按工单需要确定。

```markdown
# <ticket 标题>：验收清单

- 工单：[<标题>](../issues/<NN>-<slug>.md)
- Spec：[规格](../spec.md)
- 实现前基准：<固化 SHA>
- 待验版本：<分支、提交及未提交变更标识；足以定位实际运行内容>
- 验证环境：<依赖、配置、数据或设备>
- 启动方法：<命令或具体操作入口>
- 观察位置：<界面、日志路径或设备现象>

## 填写方法

执行每项操作，达到全部通过标准后将 `[ ]` 改为 `[x]`。未执行或未通过均保持 `[ ]`；发现问题时在“发现的问题”记录项目编号、步骤、预期与实际现象，以及可用日志。修复后确认解决时在该问题下补写确认结果。

## 验收项目

- [ ] A1：<要验证的行为>
  - 前置条件：<状态与数据>
  - 操作：<可逐步执行的动作>
  - 通过标准：<可观察、可判定的结果及必要边界>
  - 实际结果/证据：<由用户填写，可留空>

## 发现的问题

由用户按项追加；没有问题可写“无”。有问题时使用：
- P1（关联 A1）：<复现步骤、预期、实际现象、日志或截图路径>
  - 用户确认：<待确认 / 已解决及验证结果 / 撤回原因>

## 处理记录

由 agent 追加日期、问题编号、修复内容、构建结果和需复验的项目；旧版本通过记录迁入此处时保留原文与版本。
```

“验收通过”要求非空清单覆盖全部标准、当前必需项目均由用户勾选、没有未解决问题。构建成功或 agent 自评不能代替用户勾选。验收通过后由 `check-result` 调用 `code-review`，两者通过才完成工单。
