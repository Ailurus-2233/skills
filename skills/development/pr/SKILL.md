# PR 描述

读实际 diff、来源 spec 与已完成的验证记录，使用 `.adev/GLOSSARY.md` 中的领域词汇。遵守仓库 PR 模板；没有模板时用以下结构，简单改动可合并为短段落。

## 变更

先说具体问题和最终行为。需要时用最小图示、伪代码或文件职责树帮助理解；简单改动无需强行画图。

## 证据

列出实际发生的前后变化与验证：编译结果、用户手动操作及确认、界面/日志/报文或显式授权的测试。区分 agent 检查与用户验收，尚未验证的项目明确标注，不捏造截图、通过结果或设备验证。

## 合并影响

说明是否容易回退、影响范围，以及真正需要关注的配置、协议、数据迁移或设备状态变化。没有特殊风险就用一句话，不填空泛清单。

本 skill 只决定描述内容，不自动创建、发布或合并 PR；这些动作遵循当前任务的授权。重写标题和正文以反映最终改动，不保留已放弃的方案或对话过程。
