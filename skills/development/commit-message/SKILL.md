## 步骤

1. **查约定**：先看项目文档（`AGENTS.md`、`CONTRIBUTING.md` 等）有无提交信息约定，有则从其约定（type 集合、scope 取舍等）。

2. **看改动**：`git status` + `git diff --cached`（无暂存则 `git diff`）弄清本次提交实际改了什么。

3. **定 type**：按改动性质选一个：

   | type       | 改动性质                     |
   | ---------- | ---------------------------- |
   | `feat`     | 新功能                       |
   | `fix`      | 修复缺陷                     |
   | `refactor` | 重构（行为不变）             |
   | `docs`     | 文档                         |
   | `style`    | 格式、排版（逻辑不变）       |
   | `test`     | 测试                         |
   | `build`    | 构建系统、依赖               |
   | `chore`    | 其他杂务                     |

   一次提交涉及多类时，取占主导的改动。

4. **定 scope**：改动集中在明确模块/目录时用其名称；不明确时省略；项目文档约定省略时也省略。

5. **写信息**：格式 `type(scope): 描述`（scope 省略时为 `type: 描述`）。描述用中文，一句话，只写做了什么。标题说不清时加简短正文，同样只写做了什么，不需要体现 adr、 ticket 等设计时描述，也不需要有类似已经验收通过这种结果向描述。

**完成标准**：产出一条符合格式的提交信息，description 行不超过 72 字符。

## 输出方式

- **直接调用**：只输出提交信息本身，不加解释、不加前后缀。
- **工程流程收尾**：用此信息执行提交（`git commit`）。
