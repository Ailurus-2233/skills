# Wayfinder

一个模糊的想法来了：太大，一个 agent 会话装不下，而且笼罩在雾里——从这里到**目的地（destination）**的路还看不见。Wayfinding 做的是找到那条路，而不是朝目的地硬冲。本 skill 把这条路绘成一张**共享地图（map）**，然后逐个解决地图上的**决策工单（decision tickets）**——其解决产物是一个"决定"的问题，而不是要执行的构建切片——直到路线清晰。

目的地因 effort 而异，而命名目的地是绘图的第一个动作：它塑造每一个工单。它可能是要交付并迭代的一份 spec、规划开始前要锁定的一个决定、或一次就地完成的改动（比如协议结构迁移）。地图是领域无关的：工程工作、课程内容，凡符合这个形状的都能装。

## 本地约定

工单跟踪默认是**本地 markdown**，本 skill 直接使用以下约定，无需查配置：

- **地图** = `.scratch/<effort-slug>/MAP.md`，一个 effort 一张，是唯一权威工件。
- **工单（ticket）** = `.scratch/<effort-slug>/tickets/<NN>-<slug>.md`，从 `01` 起编号。
- **认领** = 把工单的 `**状态：**` 从 `open` 改为 `claimed` 并写上 `**认领人：**` 署名。
- **阻塞** = 工单头部 `**阻塞于：**` 行的文本引用（本地 markdown 没有原生阻塞关系）。一个工单在其所有阻塞项都 `closed` 时即为**未阻塞**；**前沿（frontier）** = 状态为 `open` 且未阻塞的工单，即"已知世界的边缘"。
- **按名字引用**：在人类阅读的一切内容里（口述、地图的 Decisions so far），用工单的**标题**引用它，标题里包着相对路径链接（如 `[轮询周期取值](tickets/03-poll-interval.md)`），绝不裸写编号或路径。一墙 `01, 02, 03` 没法读，名字一眼可读。

（若 `/setup-dev-workflow` 配置了真实 issue tracker，同一套概念照样适用，换成平台原生操作即可，此处不展开。）

## 规划，而非动手

Wayfinder 默认是**规划**：每个工单解决一个决策，当路已清晰、在有人去真正动手之前再没什么可决定的时候，地图就完成了。"干脆直接把活干了"的冲动，通常就是你已走到地图边缘、该交接了的信号。某个 effort 可以在它的 **Notes** 里覆盖这条默认，把执行也搬进地图；没有这种声明时，产出决策，不产出交付物。

## 地图

地图是 `.scratch/<effort-slug>/MAP.md`，唯一权威工件；它的工单在旁边的 `tickets/` 目录里。

地图是**索引，不是仓库**。它列出已做出的决策并指向持有细节的工单；一个决策只存在于一个地方——它的工单——所以地图从不复述，只做一句话摘要并链接。

### 地图正文

整张地图的低分辨率视图，每个会话加载一次。开放工单**不**列在地图里：它们就是 `tickets/` 下状态为 `open`/`claimed` 的文件，靠扫描目录找到。

```markdown
## Destination

<抵达这张地图的终点长什么样：本 effort 在寻找的那一份 spec、决定或改动。一两行；每个会话选工单前先据此定向。>

## Notes

<领域；每个会话应调用的 skill；本 effort 的长期偏好>

## Decisions so far

<!-- 索引：每个已关闭工单一行，足以判断相关性；细节顺链接去看工单本身 -->

- [<已关闭工单标题>](tickets/NN-slug.md): <答案的一句话摘要>

## Not yet specified

<!-- 见"战争迷雾"：尚不能写成工单的范围内迷雾；随前沿推进而毕业 -->

## Out of scope

<!-- 见"范围之外"：被裁定在目的地之外的工作；已关闭，永不毕业 -->
```

### 工单

每个工单是 `tickets/` 下的一个文件，正文是一个大小适配一个 100K token agent 会话的问题：

```markdown
# <NN>：<工单标题>

**类型：** research | prototype | grilling | task
**阻塞于：** <阻塞它的工单标题/编号，或 "无">
**状态：** open
**认领人：**

## Question

<本工单要解决的决策或调查>
```

会话认领工单要**最先做**：动手之前先把 `**状态：**` 改为 `claimed` 并在 `**认领人：**` 署名，让并发会话跳过它。`open` 即未认领。

答案不属于正文；它在解决时记录（见"在地图上推进"）。解决过程中产出的资料（原型文件、调研笔记）以链接形式从工单引用，不粘贴进去。

## 工单类型

每个工单要么是 **HITL**（human in the loop，与一个能自己表态的真人*一起*推进），要么是 **AFK**（agent 独立完成）。HITL 工单只能通过这种实时交流解决；agent 绝不代替人类的那一边（自问自答的 grilling agent 就破坏了这条规矩）。

- **Research**（AFK）：读文档、第三方 API 或本地资源（如知识库），挖出一个决策在等待的事实。由一个调用 Skill 工具 "research" 的子 agent 解决。当所需知识在当前工作目录之外时使用。
- **Prototype**（HITL）：通过造一个便宜、粗糙、具体、可评议的东西（大纲、草搞、桩代码、UI/逻辑代码）来提高讨论的保真度，调用 Skill 工具 "prototype"。把原型作为资料链接进工单。当关键问题是"它该长什么样/该怎么表现"时使用。
- **Grilling**（HITL）：对话，默认类型。总是调用 Skill 工具两次——"grilling" 和 "domain-modeling"。
- **Task**（HITL 或 AFK）：必须先完成、才能做某个*决策*的手工活：没什么可决定、可原型、可调研的，但讨论被它卡住。注册一个服务以便评判其 API、开通权限、搬运数据以便看清其形状。这是唯一*动手*而非*决策*的类型，它凭"解锁一个决策"而非"交付目的地"获得存在资格。agent 能独立完成的就独立完成（AFK）；否则交给人类一份精确的清单（HITL）。活干完即解决；答案记录做了什么以及后续工单依赖的事实（凭据位置、新路径、数据规模）。

## 战争迷雾

地图是**故意不完整的**：看不见就不要画。在在线工单之外是**战争迷雾**：你能感觉到要来、但还钉不死的决策与调查，因为它们挂在仍未解决的问题上。解决一个工单会清开它前方的雾，让此刻已可明确的东西毕业成新工单，一次一个，直到通往目的地的路清晰、再无工单剩余。

地图的 **Not yet specified** 节就是写下这片朦胧视野的地方：疑似的问题、以后要 revisit 的区域。它是朝向目的地的*未探索*前沿：这里的一切都在范围内，只是还不够清晰到能写成工单。视野允许多粗就写多粗、多细就写多细；它同时是给协作者看的路标，标示 effort 的走向。

**迷雾还是工单？** 检验标准是你现在能否精确陈述这个*问题*，而不是你现在能否回答它。

- 问题已经足够尖锐时**写成工单**，即使它被阻塞、暂时动不了。
- 还不能那么尖锐地表述时放进 **Not yet specified**。不要把雾预先切成工单大小的块：它比工单粗，一片雾到达前沿后可能毕业成好几个工单，也可能一个都没有。

**Not yet specified** 排除：已决定的（Decisions so far）、已是在线工单的、以及范围之外的（下一节）。

## 范围之外

雾只会朝*目的地*聚集。目的地固定了范围，所以超出它的工作是 **out of scope**：它不是雾，不属于 **Not yet specified**。它在地图上有自己的 **Out of scope** 节：你有意识地裁定为不属于*本* effort 的工作。落到这里的是范围问题，不是清晰度问题。

范围之外的工作永不毕业（前沿止步于目的地），只有当目的地被重画时它才回来——而且那时是作为一个全新 effort，而不是续作。

把某物裁定出范围是一次划界行为，不是路线上的一步。当一个已存在的工单被发现位于目的地之外（绘图时误圈进来，或被某个解决暴露出来），**关闭它**（把 `**状态：**` 改为 `closed`——关闭的工单明确地离开前沿），并在 **Out of scope** 节留一行：摘要加出局理由，链接该已关闭工单。它不进 **Decisions so far**——那里记录的是实际走过的路线，划界不是路线上的一步。

## 调用方式

两种模式。无论哪种，**每个会话最多解决一个工单**，research 工单除外。

### 绘制地图（chart）

用户带着一个模糊的想法调用。

1. **命名目的地。** 调用 Skill 工具两次——"grilling" 和 "domain-modeling"——钉死这张地图在寻找什么：那一份 spec、决定或改动。目的地固定范围，所以最先定。
2. **测绘前沿。** 再 grill 一轮，这次是**广度优先**：在整个空间上铺开，而不是在某条线上深挖，浮出开放的决策和现在就能迈出的第一步。**如果这没有浮出任何雾**（通往目的地的路已经清晰，整段旅程一个会话装得下），你不需要地图。停下来问用户想怎么进行。
3. **创建地图** `.scratch/<effort-slug>/MAP.md`：Destination 和 Notes 填好，Decisions so far 留空，把雾速写好进 **Not yet specified**。
4. **创建现在就能写清的工单**：在 `tickets/` 下逐个写文件，填好 `## Question` 与 `**类型：**`；然后在**第二遍**里连阻塞边（`**阻塞于：**`——文件得先存在才能互相引用）。连线把它们分成前沿与被阻塞两组；一切还写不清的留在雾里，即 **Not yet specified** 节。
5. **发射 research 子 agent。** 对刚创建的每个 `research` 工单，起一个调用 Skill 工具 "research" 的子 agent 并行解决它，把发现写在一次性的 `research/<name>` 分支上，并在工单里留下下文指针。
6. 停：绘图本身就是一个会话的工作量；它一个工单也不亲手解决。

### 在地图上推进（work）

用户带着一张地图（路径或 effort 名）调用。工单是**可选的**：没指定时，由你而不是用户来挑下一个决策。

1. 加载**地图**：低分辨率视图，不是每个工单的正文。
2. 选工单。用户指名了就用它；否则按顺序取第一个前沿工单。**认领它**：动手之前先把状态改为 `claimed` 并署名。
3. 解决它。**按需放大**：临时读取任何相关或已关闭工单的全文；调用 `## Notes` 节点名的各 skill。拿不准时，调用 Skill 工具两次——"grilling" 和 "domain-modeling"。
4. 记录解决结果：在工单文件末尾追加一个带日期的**解决记录**章节（写清答案与依据），把 `**状态：**` 改为 `closed`，并在地图的 Decisions so far 追加一行（标题链接 + 一句话摘要）。
5. 添加新浮出的工单（先建文件再连阻塞边）；把答案使之可明确的雾毕业成工单，同时把每片毕业的雾从 **Not yet specified** 划掉，让它只以新工单的形式存在。如果答案揭示某个工单（本个或别的）位于目的地之外，**裁定它出范围**，而不是在路线上解决它。如果这个决定推翻了地图的其他部分，更新或删除那些工单。

用户可能并行推进多个未阻塞工单，所以要预期其他会话正在并发编辑 `.scratch/<effort-slug>/` 下的文件。
