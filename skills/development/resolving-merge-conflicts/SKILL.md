---
name: resolving-merge-conflicts
description: "当需要解决进行中的 git merge/rebase 冲突时使用。"
---

1. **看清当前状态**：查看 git 历史、冲突文件，弄清这次 merge/rebase 进行到哪一步。

2. **为每个冲突找到 primary source**：深入理解每一处改动为什么这样做、原始意图是什么。读提交信息，查相关 PR，回溯原始 issue/工单（包括 `.adev/` 下的本地 markdown 工单）。

3. **逐 hunk 解决**：尽可能同时保留两边的意图；确实无法兼容时，选择符合本次合并既定目标的那一边，并记下取舍。不要借解决冲突之机发明新行为。无法安全判断取舍时保留现场并说明所缺信息，不自行丢弃任一侧的改动。

4. **发现并运行项目已有的检查**：读取仓库实际构建入口或 `.adev/agents/verification.md`；C# 项目按其约定运行 `dotnet build` 或等价命令，其他项目运行对应检查。修掉合并弄坏的东西。按项目验证配置决定是否新增后台数据流输入输出测试，客户端操作仍由用户手动验收；合并后给出受影响关键路径的手动验证步骤。

关联工单时，合并后按验证配置运行共享项目累计回归，结果交回 implement/check-result；完成 Git 操作不等于工单验收通过。

5. **完成 merge/rebase**：只暂存本次冲突解决涉及的文件，核对暂存差异后按 Git 当前操作继续。若是 rebase，逐次继续直到所有提交重放完毕；保留开始前已有的无关改动。
