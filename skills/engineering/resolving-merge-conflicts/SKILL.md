---
name: resolving-merge-conflicts
description: "当需要解决进行中的 git merge/rebase 冲突时使用。"
---

1. **看清当前状态**：查看 git 历史、冲突文件，弄清这次 merge/rebase 进行到哪一步。

2. **为每个冲突找到 primary source**：深入理解每一处改动为什么这样做、原始意图是什么。读提交信息，查相关 PR，回溯原始 issue/工单（包括 `.scratch/` 下的本地 markdown 工单）。

3. **逐 hunk 解决**：尽可能同时保留两边的意图；确实无法兼容时，选择符合本次合并既定目标的那一边，并记下取舍。**不要**借解决冲突之机发明新行为。始终完成解决，绝不 `--abort`。

4. **发现并运行项目已有的检查**：先 `dotnet build` 确认编译通过，再运行仓库里已有的其他检查脚本（如代码分析、格式检查）。修掉合并弄坏的任何东西。本仓库不写自动化测试套件——合并完成后提示用户：关键路径可能需要手动验证（启动程序、操作相关界面、确认行为符合预期）。

5. **完成 merge/rebase**：暂存所有改动并提交。如果是 rebase，继续 rebase 流程直到所有提交都重放完毕。
